{# fragments/run_status.html — a runbook run's own live status line in the chat window (contract runbook.md §3 "Progress in the chat"; PLAN.md web row, alpha.19). The transcript's own `system`-role notice lines (chat_thread._notice_entry, drawn by fragments/chat_exchange_body.html) are the run's *history* — one line per step, written once and never redrawn. This is its *now*: what `chat_run.runbook_run_view` last found when this was rendered, with the one control (Stop while running, Resume while interrupted or parked on a failure) that line owns. Never works anything out for itself — every field comes off that one dict, so the full page, the poll and a Stop/Resume's own response can never disagree about what a run is doing. POLLS ITSELF ONLY WHILE THERE IS SOMETHING LEFT TO SAY: `hx-get`/ `hx-trigger` are on this element only when `run.poll` is true, and an `outerHTML` swap replaces the whole element — attributes included. A run that has nothing left to report (no run at all, parked, stopped, done or failed) renders without them, which is what stops the polling; nothing else has to notice that a second time.
